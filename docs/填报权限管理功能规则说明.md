# 填报权限管理（一键开关）功能规则说明

> 版本：v1.0（2026-11-10）
> 适用系统：湖南民族职业学院学生综合素质测评（综测）加分申报与审核系统
> 关联功能：「填报窗口」时间限制（见《填报停用期间功能规则说明》）

---

## 1. 功能概述

超级管理员可在「填报权限」标签页 **一键开启 / 一键关闭** 全部填报相关操作，或对每个权限项 **单独开关**。开关关闭期间，对应写操作在接口层被拒绝（403），查询、导出等只读功能不受影响。

开关与时间窗口是 **两道独立的闸门，叠加生效**：一次操作要被放行，必须同时满足「权限开关已开启」且「当前处于开放的时间窗口（或未配置窗口）」。

---

## 2. 权限项定义与管辖范围

| key | 权限项 | 影响范围 | 关闭后被拒绝的操作 | 关闭后仍可用的操作 |
|---|---|---|---|---|
| `apply_submit` | 学生填报申请 | 学生端 | 学生提交加分申请（POST /api/student/applications）；学生上传证明材料（POST /api/upload） | 查看成绩 / 申请状态 / 证明材料；导出个人测评表；修改密码；AI 咨询 |
| `apply_review` | 教师审核申请 | 教师端 | 教师审核通过 / 驳回（PUT /api/teacher/applications/:id/review） | 查看申请明细与证明；查看学生总表 / 排名；各类导出 |
| `apply_edit` | 数据编辑维护 | 教师端 | 新增 / 编辑学生；批量操作（删除、改学籍、重置密码）；班级新增 / 编辑 / 删除；学生导入（Excel / CSV / JSON） | 学生总表查询；考勤查询；数据备份导出 |
| `attendance_write` | 考勤登记 | 教师端 | 考勤登记（POST）、修改（PUT）、删除（DELETE） | 考勤查询 |

通用规则：

1. **只读豁免**：一切查询与导出功能在任何开关状态下均可用；
2. **管理员豁免**：超级管理员执行上述任何操作不受开关限制（保证系统永远可被管理）；
3. **缺省开启**：某权限项从未配置（表中无记录）时视为开启，保证向下兼容；
4. **存量数据不变**：关闭不影响已提交申请、已审核结果、已写回成绩；仅冻结「新的写操作」。

## 3. 管理端操作与交互（确认提示 + 状态反馈）

### 3.1 一键全部开启 / 一键全部关闭

- 点击「🔓 一键全部开启」→ 弹出确认框，列明将开启的 4 项权限与恢复语义 → 确认后生效；
- 点击「🔒 一键全部关闭」→ 弹出确认框，**逐项列明关闭后果**（提交被拒 / 审核被拒 / 编辑被拒 / 考勤被拒）、只读豁免与存量数据保护说明 → 确认后生效；
- 操作完成后 toast 反馈「已一键全部开启 / 关闭」，列表即时刷新。

### 3.2 单项切换

- 权限项明细表每行提供「开启 / 关闭」按钮，点击弹出确认框：
  - 关闭确认框包含 **该项具体的被拒操作清单**（如关闭「学生填报申请」→ 说明提交申请与上传证明将被拒绝）；
  - 开启确认框说明恢复语义（此前被拒绝的操作需由用户重新进行）；
- 每行显示当前状态标签（开启=绿 / 关闭=红）与 **最近变更人与时间**，便于审计。

### 3.3 权限与审计

- 管理入口需权限点 `switch:manage`（管理员角色默认拥有，可在「角色权限」页调整）；
- 每次变更记录 `updated_by`（管理员账号）与 `updated_at`，列表可见。

## 4. 各端状态提示方式

| 端 | 提示方式 |
|---|---|
| 学生端 | 进入申报页自动检查：开关关闭时提交区上方显示红色提示条「⛔ 管理员已关闭『学生填报申请』功能，提交暂不可用…」，提交按钮禁用（文案「当前不可填报」）；每 5 分钟自动刷新；提交被后端拒绝时立即刷新状态 |
| 教师端 | 页面顶部显示红色横幅「🔒 管理员已暂停部分功能：『…』『…』相关操作暂不可用…」，列出全部被关闭项；横幅随开关状态自动出现 / 消失 |
| 管理端 | 「填报权限」页实时展示各权限项状态、最近变更人 / 时间、关闭项计数 |

所有前端提示均为体验优化，**后端接口校验是权威强制**（返回 403 + 明确文案：「管理员已关闭『××』功能，××暂不可用，如有疑问请联系管理员」）。

## 5. 与时间窗口的叠加关系

```
操作放行 = 权限开关开启 AND 时间窗口放行（未配置窗口视为放行）
```

| 时间窗口状态 \ 开关 | 开启 | 关闭 |
|---|---|---|
| 开放期（或未配置） | ✅ 可操作 | ⛔ 被拒（提示管理员已关闭） |
| 停用期间（未开始 / 已截止） | ⛔ 被拒（提示窗口原因 / 下一窗口） | ⛔ 被拒（提示管理员已关闭，优先展示） |

开关关闭的原因文案 **优先于** 窗口原因展示，避免用户混淆。两者互不覆盖、互不依赖，可独立配置。

## 6. 对进行中流程的影响

| 场景 | 处理 |
|---|---|
| 已提交、待审核（pending）的申请 | 完整保留；关闭审核期间教师无法处理，恢复后可继续审核，状态与写回口径不变 |
| 学生本地草稿（localStorage） | 不清理、不丢失；关闭期间冻结提交入口，恢复后可继续完成提交 |
| 已上传未关联申请的证明材料（KV） | 不删除；恢复后提交时正常关联 |
| 切换瞬间正在填写 / 正在审核的操作 | 前端已发出的请求由后端按「请求到达时刻」的开关状态判定；被拒操作 **不做排队与自动补做**，恢复后需重新操作 |
| 审核通过后的分数写回（applyScores） | 与审核在同一请求内完成：审核被拒时写回同样不会发生，不存在「审了但分没写」的中间态 |
| 导出（xlsx / docx / 备份 JSON） | 纯只读，任何开关状态下可用 |
| AI 综测咨询、数据大屏 | 不受影响 |
| 大屏统计、排名计算 | 基于存量数据，不受开关影响 |

---

## 7. 异常处理

| 异常场景 | 处理 |
|---|---|
| 关闭期间用户绕过前端直接调接口 | 后端 403 拒绝，文案明确，无越权可能 |
| 管理员误点「一键全部关闭」 | 需二次确认（确认框列明全部后果）；误操作后点击「一键全部开启」即时恢复 |
| 未知权限项 / 非法请求 | 后端校验 key 合法性，返回「未知的权限项」 |
| 并发切换 | 以最后一次写入为准（UPSERT），无中间态 |
| 状态查询失败（网络异常） | 前端不阻断页面使用；操作时仍会被后端拦截并提示 |

## 8. 验收测试用例（最小集）

1. 关闭 `apply_submit` → 学生提交申请返回 403，文案含「管理员已关闭」；学生端按钮禁用 + 红条；
2. 关闭 `apply_submit` → 学生上传证明返回 403；
3. 关闭 `apply_review` → 教师审核返回 403；教师端顶部横幅出现；
4. 关闭 `apply_edit` → 学生编辑 / 批量操作 / 班级管理 / 导入均返回 403；
5. 关闭 `attendance_write` → 考勤登记 / 修改 / 删除返回 403；
6. 关闭全部开关 → 查询、导出、AI 咨询、大屏均正常；
7. 管理员在开关关闭状态下执行审核 / 编辑 → 正常放行（管理员豁免）；
8. 「一键全部开启」→ 上述被拒操作全部恢复；pending 申请可正常审核写回；
9. 开关关闭 + 时间窗口开放 → 仍被拒（开关优先展示）；开关开启 + 窗口停用期间 → 仍被拒（窗口原因展示）；
10. 权限项列表可见最近变更人与时间。
