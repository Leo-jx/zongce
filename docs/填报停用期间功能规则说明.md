# 申报填报「停用期间」功能规则说明

> 版本：v1.0（2026-11-09）
> 适用系统：湖南民族职业学院学生综合素质测评（综测）加分申报与审核系统
> 关联功能：超级管理员端「填报窗口」配置（按学年度 / 学期的申报开放时间区间）

---

## 1. 概述与目标

系统支持超级管理员按 **学年度 + 学期** 配置各角色 / 各账号可填报申请的开放时间窗口。当当前时间不在任何启用的时间窗口内时，系统进入 **「停用期间」**：填报、审核、编辑等写操作被限制，仅保留查询、导出等只读能力。

本说明用于明确停用期间的：适用对象、触发条件、禁用与开放功能的边界、状态提示方式、停用与恢复时的处理规则，作为开发、测试与验收的统一依据。

---

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| 时间窗口（窗口） | 一条配置：配置对象（角色 / 账号）× 学年度 × 学期 × 开放时间 × 截止时间 × 启用状态 |
| **窗口停用** | 管理员将某一条窗口配置的「启用」开关关闭（enabled=0）。被停用的配置不参与任何判定，仅此而已 |
| **停用期间（限制期）** | 系统中 **存在启用中的窗口配置**，但当前时间不落在任何一条启用窗口的 [开放时间, 截止时间] 区间内（含未开始与已截止两种情形） |
| 开放期 | 当前时间落在任一启用窗口区间内 |
| 不限时 | 系统中不存在任何启用中的窗口配置（从未配置、全部被停用、或全部被删除），此时系统保持原有行为，**不做任何限制** |
| 北京时间 | 所有窗口时间统一按 UTC+8 存储与校验（格式 `YYYY-MM-DD HH:MM:SS`）；判定一律以 **服务器北京时间** 为准 |

> ⚠️ 重要区分：「窗口停用」（关闭某条配置）≠「停用期间」。**手动停用全部窗口配置会使系统回到「不限时」状态**，而不是进入停用期间。管理员如需临时冻结填报，应配置一条时间上不覆盖当前时刻的窗口（例如已截止窗口），而不是停用唯一启用的窗口。

---

## 3. 适用对象

| 对象 | 是否受停用期间影响 | 说明 |
|---|---|---|
| 学生（role=student） | ✅ 受限 | 禁用申请提交等写操作，保留只读功能 |
| 辅导员 / 教师（role=teacher） | ✅ 受限 | 禁用审核、编辑等写操作，保留只读功能 |
| 超级管理员（role=admin） | ❌ 不受限 | 管理配置本身（窗口管理、账号管理、数据维护）必须始终可用，否则系统将无法恢复 |
| 访客（guest） | ❌ 不适用 | 无登录态，仅能浏览公开说明页 |
| 系统自动行为（AI 咨询、自动初始化等） | ❌ 不受限 | 非填报 / 审核链路 |

**窗口配置的命中范围**（决定「谁」受限）：

- `scope=role`：命中该角色的全部账号；`role=all` 的窗口对 **学生与教师所有账号** 同时生效；
- `scope=account`：仅命中指定账号（学号 / 教师号），用于个案精确控制（如单独放行某学生补报、单独冻结某账号）；
- 同一账号同时命中多条窗口（账号级 + 角色级 + 全部角色）时，判定为 **并集**：落入任意一条启用窗口即视为开放，各窗口之间无优先级覆盖关系。

## 4. 触发条件

### 4.1 判定算法（服务端统一执行）

```
设当前服务器时间为 T（北京时间）：
1. 取该账号命中的全部「启用中」窗口集合 W =
     { w | w.enabled=1 且 ( w.scope=account 且 w.account=当前账号
                           或 w.scope=role 且 (w.role=当前角色 或 w.role=all) ) }
2. 若 W 为空 → 不限时：所有功能正常；
3. 若 ∃ w∈W 使 w.start_at ≤ T ≤ w.end_at → 开放期：所有功能正常；
4. 否则 → 停用期间（限制期）。
```

### 4.2 进入停用期间的情形

| 情形 | 触发条件 | 典型场景 |
|---|---|---|
| A. 窗口未开始 | 存在启用窗口且全部满足 `start_at > T` | 管理员提前配置了下学期的填报窗口 |
| B. 窗口已截止 | 存在启用窗口且全部满足 `end_at < T` | 填报截止后进入审核统计阶段 |
| C. 配置不覆盖当前时刻 | 启用窗口存在但区间与 T 不相交 | 管理员只配置了某个特定日期段 |

### 4.3 判定的权威性与时效

- 判定 **始终以服务端校验为准**（后端在每次写操作时实时判定），前端提示仅为体验优化，两者不一致时以后端为准；
- 学生端提示状态每 5 分钟自动刷新一次，管理员修改窗口配置后最迟 5 分钟内（或刷新页面后立即）反映到前端；
- 学期字段（整学年 / 第一学期 / 第二学期）为窗口的 **标注信息**，参与展示与统计归类，不参与时间判定；时间判定只依据 `start_at / end_at`。

## 5. 功能限制边界（禁用与保留范围）

### 5.1 学生端

| 功能 | 停用期间 | 说明 |
|---|---|---|
| 提交加分申请 | ⛔ 禁用 | 后端 `POST /api/student/applications` 返回 403 与原因文案；前端提交按钮禁用并显示提示条 |
| 上传新的证明材料 | ⛔ 禁用 | 随提交入口一并禁用（证明材料服务于申请提交） |
| 修改 / 清空本次申报草稿 | ⛔ 禁用 | 草稿数据不丢失，仅冻结入口（见 7.2） |
| ✅ 查看本人综测成绩 | 开放 | 只读 |
| ✅ 查看申请记录与审核状态、驳回理由 | 开放 | 只读（含停用前已提交申请的进度跟踪） |
| ✅ 查看已上传证明材料 | 开放 | 只读 |
| ✅ 导出个人测评表（docx） | 开放 | 纯前端本地生成，属导出类只读功能 |
| ✅ 修改本人密码、AI 综测咨询 | 开放 | 与填报链路无关 |

### 5.2 教师 / 辅导员端

| 功能 | 停用期间 | 说明 |
|---|---|---|
| 审核加分申请（通过 / 驳回） | ⛔ 禁用 | 后端审核接口返回 403；前端审核按钮禁用并显示横幅提示 |
| 编辑学生信息 / 成绩（含五育明细、批量修改） | ⛔ 禁用 | 写接口返回 403 |
| 批量操作（删除 / 改学籍状态 / 重置密码） | ⛔ 禁用 | 属编辑类写操作 |
| 导入学生（Excel / CSV / JSON）/ 班级管理（新建、编辑、删除班级） | ⛔ 禁用 | 属数据编辑类操作 |
| 考勤登记 / 修改 | ⛔ 禁用 | 属编辑类写操作 |
| ✅ 查看申请明细与证明材料 | 开放 | 只读（可预先完成材料核验，恢复后直接审核） |
| ✅ 查看学生总表、排名、考勤查询 | 开放 | 只读 |
| ✅ 导出综测成绩 / 名单（xlsx、备份 JSON） | 开放 | 导出类只读功能 |
| ✅ 数据备份导出 | 开放 | 只读 |

### 5.3 超级管理员端

全部功能 **不受限**（含审核代操作、数据维护、窗口配置管理）。特别地：

- 「填报窗口」配置页在停用期间仍可正常增删改查 —— 这是解除停用的唯一入口；
- 管理员代教师 / 学生执行的写操作不受停用限制（管理行为优先）。

### 5.4 边界界定原则

1. **读写分界**：一切改变数据的操作（提交、审核、增删改、导入、登记）在停用期间一律拒绝；一切查询与导出一律开放。
2. **角色分界**：限制只作用于学生与教师两个角色；管理员永不受限。
3. **已发生数据不回溯**：停用不影响此前已提交申请、已审核结果、已写回成绩的有效性；仅冻结「新的写操作」。
4. **接口级强制**：限制在后端接口层强制执行（403），即使绕过前端直接调用接口也无法越权。

## 6. 状态提示方式

### 6.1 学生端（student.html）

| 状态 | 提示形式 |
|---|---|
| 开放期（命中窗口） | 提交区上方绿色提示条：「✅ 本次填报窗口开放中：\<学年度\>学年 \<学期\>（开放时间 ~ 截止时间），请在截止前提交」 |
| 停用期间（未开始） | 红色提示条：「⛔ 当前不在可填报时间窗口内。下一窗口：\<学年度学年\>（起 ~ 止），如有疑问请联系管理员」；提交按钮禁用、文案变为「当前不可填报」 |
| 停用期间（已截止） | 红色提示条：「⛔ 本角色的填报窗口均已截止（最近窗口 …于 \<时间\> 结束），如有疑问请联系管理员」；提交按钮禁用 |
| 不限时 | 不显示提示条，提交按钮正常 |

提示条每 5 分钟自动刷新；提交被后端拒绝时立即重新拉取状态，保证按钮文案与实际限制一致。

### 6.2 教师 / 辅导员端（teacher.html）

- 页面顶部显示黄色横幅：「⛔ 当前不在填报时间窗口内，审核与编辑功能已暂停（\<原因与下一窗口信息\>）」，审核 / 编辑 / 导入 / 考勤登记按钮禁用并附 title 说明；
- 列表、详情、导出按钮保持可用；
- 【待实现】当前版本教师端仅展示限制提示，接口级强制见第 8 节实施状态。

### 6.3 管理端（admin.html）

- 「填报窗口」列表每条配置显示实时状态标签：**开放中（绿）/ 未开始（蓝）/ 已截止（灰红）/ 已停用（灰）**，并展示服务器时间，便于管理员核对判定基准；
- 修改窗口配置保存后立即生效，无需重启。

### 6.4 后端拒绝响应规范

- HTTP 状态 403，响应体 `{ code:403, msg:"<原因文案>", data:null }`；
- 原因文案必须包含：限制事实 + 下一窗口 / 截止时间（若有）+ 引导话术（「如有疑问请联系管理员」）。

## 7. 停用与恢复时的处理规则

### 7.1 进入停用期间

1. **自动生效**：到达截止时间或处于未开始区间时系统自动进入限制态，无需人工干预；
2. **手动干预**：管理员启用 / 停用 / 修改 / 删除窗口配置即时生效（下次判定即采用新配置）；
3. **在途数据不中断**：
   - 已提交（pending / approved / rejected）的申请与审核记录完整保留，状态不变；
   - 学生本地草稿（浏览器 localStorage）与已上传未关联的证明材料（KV，application_id=NULL）**不清理、不丢失**；
4. **不做操作排队**：停用期间被拒绝的提交 / 审核不做暂存与自动补做，需在恢复后由用户重新操作。

### 7.2 恢复（解除停用）

恢复途径（任一即可）：

| 途径 | 操作 |
|---|---|
| 自然恢复 | 预配置的下一窗口到达 `start_at`，系统自动开放 |
| 修改现有窗口 | 管理员将窗口区间修改为覆盖当前时刻 |
| 新增窗口 | 管理员新建一条覆盖当前时刻的启用窗口 |
| 删除 / 停用全部窗口 | 系统回到「不限时」状态（慎用，属全局放开） |

恢复后的行为：

1. 学生端、教师端被禁用的按钮与入口 **立即恢复**（前端最迟 5 分钟内自动刷新，刷新页面立即生效）；
2. 学生可继续使用停用前的草稿与已上传证明完成提交，提交时正常关联证明材料；
3. 教师可继续审核停用前积累的 pending 申请，审核写回口径（奖励分累加、扣分累加）与正常期完全一致；
4. 不产生任何补偿性 / 批量性自动动作（不自动通过、不自动驳回、不自动提醒补交）。

### 7.3 异常与边界场景

| 场景 | 处理 |
|---|---|
| 管理员配置了 start ≥ end 的窗口 | 后端保存时直接拒绝（「开放时间必须早于截止时间」） |
| 账号级与角色级窗口冲突 | 并集判定，命中任一即开放（账号级用于「例外放行 / 例外冻结」） |
| 服务器与本地时钟偏差 | 判定一律以服务器北京时间为准；前端提示中的倒计时仅供参考 |
| 停用期间学生尝试绕过前端直接调接口 | 后端 403 拒绝，无越权可能 |
| 全部窗口被删除 / 停用 | 系统回到不限时状态（保持向下兼容，避免误配置导致全员锁死） |
| 停用期间到达大屏统计 / AI 咨询 / 导出 | 均不受影响，正常服务 |

## 8. 实施状态与验收要点

### 8.1 实施状态

| 能力项 | 状态 |
|---|---|
| 窗口配置 CRUD（角色含「全部」、学期含「整学年」、学年度扩展） | ✅ 已上线 |
| 学生端提交限制（后端 403 + 前端提示条 / 按钮禁用） | ✅ 已上线 |
| 学生端窗口状态查询接口 `GET /api/student/apply-window` | ✅ 已上线 |
| 教师端审核 / 编辑 / 导入 / 考勤登记的接口级限制 | ⏳ 待实现（本说明 v1.0 定义的需求项） |
| 教师端顶部限制横幅与按钮禁用 | ⏳ 待实现 |
| 权限点 `window:manage`（管理员默认拥有，可在角色权限页调整） | ✅ 已上线 |

### 8.2 验收测试用例（最小集）

1. 配置一条覆盖当前时刻的学生角色窗口 → 学生可正常提交；
2. 将窗口改为已截止区间 → 学生提交返回 403，文案含截止时间；前端按钮禁用；
3. 配置未开始的下一窗口 → 提示条显示「下一窗口」信息；
4. 停用全部启用窗口 → 提交恢复可用（不限时）；
5. 按账号为学生 A 配置覆盖当前时刻的窗口、角色级窗口已截止 → 仅学生 A 可提交；
6. `role=all` 窗口开放时 → 学生与教师账号均命中；
7. 停用期间：学生成绩 / 申请状态查看、个人测评表导出正常；教师查看与导出正常；
8. 恢复开放后：学生草稿 + 已上传证明可正常完成提交并关联；
9. 教师端审核接口在停用期间返回 403（待实现项验收）。

## 9. 附：配置操作指引（管理员）

1. 登录超级管理员端 → 「填报窗口」标签页；
2. 选择配置对象（全部角色 / 学生 / 辅导员教师 / 按账号）→ 学年度 → 学期（整学年 / 第一 / 第二学期）→ 开放与截止时间 → 勾选「启用」→ 保存；
3. 可配置多条窗口（如每学期各一条）；按账号配置可实现个别学生补报或个别账号冻结；
4. 临时冻结填报：新增一条起止时间均在过去（或未来）的启用窗口即可；**不要**通过停用全部窗口来实现冻结（停用全部 = 不限时）；
5. 所有配置修改即时生效，列表页可见服务器时间与每条窗口的实时状态。
